# Portfolio Reflections: Agile & Software Development

How do I interpret user needs and implement them into a program? How does creating “user stories” help with this?
When it comes to building software, you can't just dive into coding and hope for the best; you have to actually understand what the user is trying to solve. I like to start by looking at the big picture and figuring out what the core problem is. 

This is where user stories are a lifesaver. Using the format, "As a user, I want to do something so that I get this result" forces you to look at things from their perspective instead of getting bogged down in technical jargon right away. It keeps you focused on building features that people will actually use, and it makes it way easier to split big ideas into smaller, bite-sized tasks with clear goals.

How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?
I approach development by breaking everything down into small, manageable pieces instead of trying to build the whole app all at once. I like to get a basic, working version up first, test it out, and then build on top of it. 

Going forward, I definitely want to stick with Agile practices. A few things I really want to keep in my workflow:
Sprints: Breaking work into short 1- to 2-week blocks keeps things moving fast and prevents burnout.
Sprint Reviews & Retrospectives: Taking time at the end of a sprint to look at what worked, what didn't, and what we can tweak is super helpful for constantly getting better.
Backlog Grooming: Keeping task lists organized so we always know what's top priority.

What does it mean to be a good team member in software development?
At the end of the day, software development is a team sport. Being a great teammate isn't just about writing clever code, it’s mostly about how you work with people. To me, being a solid team member means:
Communicating early: If you get stuck or run into a bug, call it out early instead of struggling in silence.
Being open with code reviews: Giving friendly, constructive feedback and not taking critiques on your own code personally.
Having each other's backs: Helping out teammates when a sprint gets tight and sharing what you know so the whole team levels up together.
